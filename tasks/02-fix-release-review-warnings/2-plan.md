### 4. Own and reap publication-test processes

1. Introduce test-only process support, such as `tests/release_test_support.py` and a dedicated per-invocation supervisor entry point. Replace the common `subprocess.run(..., timeout=90)` invocation with a supervised launch that preserves stdout/stderr, ordinary exit-result assertions, sentinel checks, and the 90-second execution timeout. Keep supervision out of production scripts and do not enable process-adoption behavior in the shared unittest runner.
2. Before launching any release process, the dedicated supervisor must enable Linux child-subreaper semantics using `prctl(PR_SET_CHILD_SUBREAPER, 1)` through the standard-library `ctypes` interface and verify that setup succeeded. Use separate inherited control pipes: the supervisor announces readiness, the harness registers cleanup, then the harness sends permission to start the release. If setup or the bounded handshake fails, do not launch the release. Linux `/proc`, subreaper support, and PID-file-descriptor signaling are explicit requirements for these supervision tests; unsupported environments must report a clear skip/blocker and cannot certify timeout remediation. No privileged installation or global process setting is allowed.
3. Make the supervisor the parent of the lock owner and the nearest surviving subreaper for its descendant tree. It must record the root and discover descendants through actual parent/child relationships while they are live; after an intermediate parent exits, its orphaned descendants become children of this supervisor, so ancestry loss does not end ownership. Open PID file descriptors for identified live processes and signal through them to prevent PID reuse from targeting unrelated processes. Recheck parentage when acquiring a process handle. Session IDs and command names are supplementary diagnostics, never sufficient ownership evidence. Do not depend on a one-time late `/proc` scan or on the original process group containing every child.
4. On timeout, assertion failure, interruption, or explicit cancellation, request teardown over the control channel; control-channel EOF must also initiate teardown. The supervisor first sends SIGTERM through the live lock owner's process handle so its existing handler forwards termination to the Bash child session. Give cooperative cleanup a bounded grace period, for example five seconds, while continuing to drain output, discover owned descendants, and reap exited direct/adopted children. Preserve the original timeout/failure outcome instead of reporting an interrupted release as success.
5. If graceful cleanup expires, the supervisor must escalate against owned survivors across all sessions, including the lock owner if still alive. Use PID-file-descriptor signaling, repeatedly discover newly adopted children, and reap with `waitpid` until no owned children remain or a separate bounded escalation deadline expires. Killing an ancestor must not terminate the supervisor before it adopts and reaps surviving descendants. Normal completion must also account for descendants that outlive the root; an exited lock owner alone does not establish teardown success. Never use process-name matching, global `pkill`, broad `/tmp` deletion, or signals against unrelated processes.
6. Use nonblocking output/control handling with explicit deadlines and output bounds, not unbounded `communicate()` calls or waits for inherited pipe EOF. Retain release output separately from supervisor status so control messages do not change existing stdout/stderr assertions. Send a completion acknowledgement only after owned children have been reaped and output/child descriptors closed; the harness then waits for the supervisor and closes its own control descriptors. A failed teardown deadline is an explicit infrastructure failure: retain ownership evidence and the isolated fixture for diagnosis rather than falsely acknowledging cleanup or removing paths beneath live processes.
7. Track run-owned `bash-release.*` directories only within the invocation's disposable fixture base, which is already supplied as `TMPDIR`. On cooperative exit, assert the production traps removed them. If escalation prevented shell traps, remove only those recorded, non-symlink run directories after confirmed descendant termination and reaping; leave the fixture Git repository and lock file available for lock assertions until test cleanup. Check that no live holder remains and the lock is acquirable, then allow ordinary fixture-directory cleanup. Never follow a cleanup target outside the owned fixture or touch shared temporary paths. Report normal trap cleanup and forced harness cleanup distinctly.
8. Reuse the ownership helper in special progress/signal tests where appropriate, retaining their synchronization barriers and behavior assertions. Permit streaming progress observation and explicit signaling of the supervised lock owner without bypassing the supervisor's adoption boundary. Keep test-only lifecycle controls out of production code unless a separately diagnosed production defect requires revising the scope.
9. Add deterministic regressions for readiness/setup failure before launch, a short timeout after a command and descendant enter a controlled wait, successful exit, nonzero exit, and harness cancellation/control-channel closure. Test both cooperative forwarding and forced escalation. The escalation case must synchronize an intermediate parent's exit while a descendant in another session ignores SIGTERM and retains an output pipe; prove that the supervisor adopts, terminates, and reaps it before acknowledging completion. Assert bounded output handling, no delayed marker/mutation, no unreaped owned children, an acquirable lock, and appropriate normal or forced cleanup of run-owned paths. Include an unrelated control process that must remain untouched. Use barriers and bounded waits rather than sleeps as the primary synchronization.

## Acceptance Criteria

- Post-promotion observation of the predecessor, absence, foreign state, or failed evidence stops before release/association writes. Pre-promotion predecessor acceptance and all supported retry paths remain intact; no rollback or destructive repair is introduced.
- Native Docker CLI tests demonstrate that the private-auth boundary preserves the selected Buildx implementation and search precedence. Original unrelated credentials and helpers remain excluded, and context/host/builder selection regressions pass.
- A dedicated test-only subreaper establishes ownership before launch. Cooperative timeout and forced intermediate-parent-exit scenarios terminate and reap owned descendants across sessions using PID-safe signaling, close output/control descriptors within bounded deadlines, and release locks before completion acknowledgement and fixture deletion. Unrelated processes remain untouched. Forced cleanup removes only verified run-owned paths after reaping, and unsupported capability or incomplete teardown is explicit rather than reported as success. Normal successful and failed commands retain existing assertions and the 90-second execution timeout.
- Release tests run with an available preferred temporary directory and with an absent preferred path, without requiring or modifying shared `/tmp/opencode` state. All existing cases remain discoverable and new regressions execute.
- Upstream baseline and local adaptations are accurately distinguished in documentation and hash assertions. Source version, npm metadata, configured notes, and operator links agree; offline validation remains credential-free and side-effect-free.
- Relevant Python, shell, native plugin-discovery, formatting, lint, type-check, unit, and application-build checks pass, or precise blockers are recorded without claiming the affected warning resolved.
- Publication remains a separate, gated activity. No source push, live publication, remote mutation, privileged preparation, unrelated-file cleanup, or image/browser acceptance claim occurs in this task.

## Risks And Decisions

- This task chooses explicit minimal downstream patches, not an unreviewed upstream upgrade. Plan/code review must assess those patches before any release-readiness decision; the prior N1/N2 warnings are not waived by planning them away.
- Docker plugin discovery is implementation-sensitive. Validate actual Docker CLI behavior, ordered extra directories, config-local candidates, and system fallback; matching version strings or fake connection tests cannot establish executable selection. If preservation cannot be demonstrated for a supported configuration, refuse it and report the limit rather than silently switching implementations.
- Referenced plugin binaries and discovery directories remain trusted operator-controlled executable inputs. Preserving discovery does not protect against their concurrent replacement or hostile filesystem changes. Do not claim binary immutability or distributed writer exclusion from local path preservation.
- Timeout teardown spans multiple sessions and process groups. The selected design is a per-invocation Linux child-subreaper supervisor with a pre-launch readiness handshake and PID-file-descriptor signaling, not runner-wide adoption or a late ancestry scan. Graceful forwarding is primary; bounded escalation must reap adopted descendants and prove completion before fixture deletion. Kernel/Python capability limits and incomplete teardown must be reported without privileged setup or a weakened success claim. Do not assert that this leak caused the previous unrelated intermittent failures without evidence.
- Changing protocol hashes intentionally prevents adoption of old-format identity evidence. Preserve historical checkouts; no tag rewriting, remote cleanup, or recovery migration belongs in these fixes.
- `0.7.9` is provisional source metadata. Image-build crashes, architecture-specific runtime checks, browser acceptance, authenticated remote version availability, exclusive writers, and clean already-pushed `main` remain independent publication gates after these warnings are fixed.
